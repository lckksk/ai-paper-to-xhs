# 小红书笔记模板（单篇规格书）

> **定位**：`/jiedu-lunwen` 成稿步骤读本文件，它只回答「一篇笔记长什么样」。
> 文字怎么改 → humanize-writing 的 8 遍工序 + `.agents/skills/jiedu-lunwen/references/中文AI味清单.md`
> 流程顺序与发布合规 → `.agents/skills/jiedu-lunwen/SKILL.md` 的「流程」与「红线」

## 硬约束

- 标题 ≤20 字；正文（含标签）≤1000 字，写完用 count_body.py 实测，超了就删不注水
- 每个数字/论断能定位到原文出处，逐条记入该篇的 事实核对.md
- 配图 3:4（1242×1656 px），三张：封面卡 / 方法卡 / 成绩卡

## 深度要求（"复述"与"解读"的分界，四条至少做到两条）

- **机制解释**：不停在"是什么"，至少讲透一个"为什么"（例：不说「质量比数量重要」就完了，补上「RL 的学习信号来自有时对有时错的题」）
- **诚实边界**：至少一处明确限定——相关≠因果、适用范围、论文没做什么
- **数字带语境**：从多少到多少、跟谁比、指标是什么，不给孤立大数
- **收录反方意见**（对标井底之硅）：至少一处引用社区/同行的质疑并公允回应——「流量起来了，纠正也跟着来了」，这是最强的信任装置

## 正文骨架（叙事流，按需合并调序，不逐条贴标签）

```
事件一句话 → 为什么值得在意 → 怎么做（讲人话）→ 结果数字
→ 比数字更值得看的细节（1-2 个）→ 边界局限 → 来源行
```

- 开头两句是生死线：最反直觉的判断放最前，用**分镜式开场**——一句一段、动词驱动、信息逐层加码（示范：「2015年，何恺明画了一条线。」）
- 技术铺垫用**限时科普模块**显式打包：「先用30秒搞懂 X 在干什么」，保证任何读者跟得上后文
- 每段 ≤3 行；段落之间靠内容衔接，不靠「首先/其次」
- 结尾可选**首尾呼应**：回到开头的意象或人物，形成闭环（井底之硅式收尾）

## 标题（≤20 字）

- **陈述洞见式（首选）**：把全文最反直觉的判断放进标题（「AI编程进步快，因为代码能自动判对错」）
- **动作细节式**：真实动作并列（「自己出题，自己判卷，自己防作弊」）
- **数字对比式**：10% → 21.7%，这个能力怎么来的
- **冲突动词式**（对标新智元，克制使用）：给事件加一个动词戏——「连夜挖走」「搞砸了」「一刀切掉」；红线：禁用「秒了/吊打/杀疯了」级夸张词
- 忌：悬念空钩（「AI 要学会"这个"了」）、营销词（炸裂/真相/必看）

## 标签（3-5 个）

大标签带流量 + 小标签定人群：`#人工智能 #AI论文 #大模型 #AI编程 #程序员`

## 配图

- **封面卡**：大标题 ≤12 字 + 一句副标题 + 角标（栏目名/日期，不带期数——发布前有人工挑选层）
- **方法卡 / 成绩卡**：步骤拆解 / 关键数字对比
- 设计与渲染规范：`.agents/skills/jiedu-lunwen/references/卡片规范.md`

## 发布（人工步骤，AI 不代劳）

1. 终审该篇 事实核对.md：论文事实逐条核对、解读观点确认认可、人设表述确认属实
2. 发布时勾选「内容由 AI 辅助生成」声明
3. 发布 48-72 小时后回填 topics.xlsx 发布记录，复盘反哺下期选题
