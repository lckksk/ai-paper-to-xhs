# 发布前检查清单

> 成稿后、交付用户终审前，过一遍本清单。1、2 由 `scripts/count_body.py` 自动检查，
> 3-6 逐条人工过。来源：社区发布前诊断方法（xiaohongshu-doctor）拆解 + xiaohongshu-mcp
> README 运营知识，详见 `research/小红书自动化调研/`。

## 1. 平台硬限（脚本自动）

- 标题 ≤ 20 字符
- 正文（含标签）≤ 1000 字符
- **图片路径不含中文**（xiaohongshu-mcp 发布的已知失败原因；若代发布，先把 PNG 复制到纯 ASCII 路径）

## 2. 敏感词扫描（脚本自动，命中逐条判断）

count_body.py 会扫描三类风险词并输出命中上下文：

| 类别 | 典型词 | 处理 |
|---|---|---|
| 极限词（虚假宣传） | 最强/最快/第一/唯一/绝对/100%/秒杀/吊打/碾压… | 厂商或榜单的**原话归因**（「Anthropic 自称」「xx 榜第一」）可保留，加「据 X」；自己下的评语 → 改写成具体事实（「跑分超过 X」而不是「最强」） |
| 承诺/夸大 | 保证/稳赚/必涨/零风险/永久 | 科技解读号基本用不到，出现即删 |
| 引流 | 加微信/私信我/扫码/二维码/外链暗示 | 出现即删；我们的人设不引流 |

判据：极限词不是一律禁——「据 Labs 官方博客，这是他们最聪明的模型」是转述，可以；
「这是史上最强模型」是自评，删或改。拿不准就改成可核实的具体数字。

## 3. 关键词布局

- 核心词（模型名/技术名）出现在：标题 + 首段前 50 字 + 标签
- 标签 5-8 个：#核心词 + #长尾词（如 #AI编程）+ #人群词（如 #程序员）
- 不堆砌：同一关键词正文出现 2-3 次足够

## 4. 首段黄金 50 字

首段四要素：核心关键词 + 痛点/好奇点 + 继续读的钩子 + 与封面卡文案呼应。
我们的分镜式开场偏情绪，检查核心词是否进了前 50 字，没有就把模型名/技术名前移。

## 5. 收藏价值自查（复盘发现：高收藏 = 信息密度路线）

至少占一项：清单/步骤可照做、对比测评、避坑提醒、可复用的数字或结论。
纯情绪叙述收藏率低；如果全篇没有「值得存下来」的块，回成稿补一个（如「三句话总结」块）。

## 6. 互动引导

结尾提问自然、具体（针对内容本身），不用营销腔（「速来」「不容错过」「码住不谢」）。
