# 真实素材规范（截图卡）

> 2026-10-20 定。解决的问题：卡片全是排版文字和 AI 拼的图，读者一眼看出「这是 AI 做的」，没有可信度。
> 原则一句话：**能用真实页面截图的，绝不用纯排版；宁可少一张卡，不编一张假图。**

## 一、为什么必须上图

- 小红书的信息流里，「有图有真相」的帖点击率与收藏率明显高于纯文字卡
- 截图是**可核验证据**：读者能顺着 arXiv 编号、GitHub 仓库名、官网 URL 自己复核
- 反过来说，编造的数字卡一旦被指出，账号人设直接崩

## 二、素材源优先级

| 级别 | 素材类型 | 例子 |
|---|---|---|
| ① 一手证据 | 官方发布的原始页面 | arXiv 摘要页、GitHub 仓库页、官方博客/公告、官方文档、HF 榜单 |
| ② 官方物料 | 官方发布的配图/演示视频首帧 | 公众号文章内图、产品截图、官方 benchmark 图 |
| ③ 权威媒体 | 有署名的报道页面 | 新华社、路透、The Verge、TechCrunch |
| ④ 二手聚合 | 榜单聚合站、转载 | orangebot.ai、科技媒体转述（只作线索，不作最终证据） |

- **①优先**。同一事实有 ① 时，卡片主视觉必须用 ①。
- ④ 只能用来找选题，成稿里的截图和数字要去 ① 复核。
- ❌ 禁止：AI 生成的「像截图一样的图」、手搓的假界面、编造的控制台/榜单。

## 三、每帖最低要求

| 帖型 | 真实截图数量 | 放哪里 |
|---|---|---|
| 每日热点帖（3-5 卡） | **≥ 2 张** | 封面卡 1 张主视觉 + 至少 1 张内容卡 |
| 周日合集帖 | **每篇 1 张**（7 篇 = 7 张） | 精华卡上半区 |
| 深读单篇 | ≥ 3 张 | 封面 + 方法卡 + 结果卡 |

- 封面卡必须有真实元素：**没有真实主视觉的封面卡不算合格**。
- 允许 1 张纯信息卡（结论/怎么用/引导），但不能是封面。

## 四、抓图工具

```bash
# 1) 写任务文件 shots-task.json（放成稿目录）
# 2) 跑
NODE_PATH=C:/Users/Lenovo/.workbuddy/binaries/node/workspace/node_modules \
  "C:/Users/Lenovo/.workbuddy/binaries/node/versions/22.22.2-6/node.exe" \
  <skill>/scripts/fetch_shots.js --task shots-task.json --out ./shots
```

产出 `shots/<name>.png`（2x 高清）+ `shots/shots.json`（标题、最终 URL、尺寸、失败原因）。

### task.json 字段

```json
{
  "viewport": { "width": 1280, "height": 900 },
  "scale": 2,
  "proxy": "http://127.0.0.1:7897",
  "shots": [
    { "name": "arxiv-abs", "url": "https://arxiv.org/abs/2610.21601",
      "sel": "#abs", "pad": 34, "maxW": 1045, "maxH": 500,
      "hide": ["#extra-services"] }
  ]
}
```

- `sel` 截元素，`pad` 外扩像素；`clip` 精确矩形（优先于 sel）；都不给则截首屏
- `maxW` / `maxH` 限制尺寸，保证多张图在卡片里等宽等高
- `hide` 关掉侧栏/弹窗/订阅条（常见 cookie 条会自动隐藏）
- `unstick` 默认 true，把 sticky 导航改成 static，避免遮挡
- `proxy`：HF、部分外媒需要 `http://127.0.0.1:7897`；arXiv、GitHub 直连即可

## 五、常用站点怎么截（实测参数）

| 站点 | 参数 | 说明 |
|---|---|---|
| arXiv 摘要页 | `sel:"#abs"`, `pad:34`, `maxW:1045`, `maxH:500`, `hide:["#extra-services"]` | 得到标题+作者+摘要；1045 是内容列宽，再宽会带右侧栏碎片 |
| HF 论文周榜 | `clip:{x:0,y:0,width:1280,height:690}` | 含 logo + Daily Papers + Weekly 视图 + 首行三张卡；**一定要等图片解码**（工具已内置） |
| HF 单篇论文页 | `clip:{x:0,y:0,width:1280,height:820}` | 含赞数、作者、Abstract |
| GitHub 仓库页 | `sel:"main"`, `maxH:800` | 含 star/fork 数、文件列表，数字极有说服力 |
| 官方博客 / 公告 | 首屏 `maxH:900`，或 `sel:"article"` | 保留站名与日期 |
| 微信公众号文章 | 见 `fetch_assets.js` 老脚本（页内 fetch + Referer 下载正文图） | 正文图比整页截图更清晰 |

## 六、嵌进卡片

用 `skill/assets/卡片组件.js` 的 `shotBox()`，它会给截图加一层**浏览器地址栏外壳**（三个圆点 + 圆角地址栏 + 域名），这是「这是真网页」最强的视觉信号。

```js
const C = require("<skill>/assets/卡片组件.js");
const ctx = C.init({ accent: "1D4ED8", accentDeep: "1E40AF", tint: "E4ECFB" });

C.shotBox(ctx, slide, {
  path: "shots/arxiv-abs.png",
  x: 0.5, y: 2.02, w: 6.5, h: 3.2, fit: "contain",
  url: "arxiv.org/abs/2610.21601",   // 地址栏文字，必须与实际 URL 一致
  dark: false,                       // 深底封面卡传 true
});
```

硬性要求：
- **地址栏文字必须与真实 URL 一致**（可以省略 `https://`），不许装饰性乱写
- 图下方必须有图注：编号/日期/「摘要原文未改动」这类可核验信息
- 卡片底部来源行写清出处与抓取时间
- 不要给截图加滤镜、圆角、投影、旋转，保持「原样截取」的观感
- 不要拉伸变形；比例不对就 `fit:"contain"` 或换一张图

## 七、数据一致性铁律

> 截图上的数字和正文里的数字对不上，是这类内容最容易翻车的地方。

1. **同一时点抓取**：正文数字与截图必须来自同一次抓取/同一次快照
2. 若榜单在动（HF 赞数每天涨），正文注明「截至 YYYY-MM-DD 快照」
3. 换数据源就必须同步换截图。不同源的数字不能混用（例：HF 官方页赞数 ≠ 某聚合站赞数）
4. 图注里带上日期，读者才知道这是快照不是实时

## 八、合规

- 截图引用属于评论/介绍性使用，但要**标注来源**（卡片来源行 + 正文来源清单）
- 不截付费墙内全文、不截他人隐私信息（个人主页、私信、订单）
- 涉及真实人物的新闻截图，脸部不放大、不做表情包式加工
- 不截含个人手机号/身份信息的界面

## 九、抓不到怎么办

按顺序退让，不许编：

1. 换另一个 ① 级源（arXiv 抓不到换 HF 论文页）
2. 换 ② 级官方物料（官方推文配图、官方演示视频首帧）
3. 退到 ③ 级权威媒体报道截图
4. 都不行就**不上图**，改纯信息卡，并在事实核对里注明「无可用一手页面素材」
