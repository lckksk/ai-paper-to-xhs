# 卡片视觉规范（HTML 引擎 · 2026-10-21 版）

> 适用：每日热点帖、周日周刊、任何 3:4 小红书配图。
> 引擎：`skill/assets/卡片-HTML/cards.js`（生成 HTML）+ `render.js`（Playwright 截图）。
> 参考实现：`posts/2026-W42/周刊-2026-10-18-本周AI前沿TOP7/卡片-编辑风.js`

## 一、为什么换掉了 pptx

旧的 `卡片模板.js`（pptxgenjs + LibreOffice 渲染）有三个结构性缺陷，不是调参能救的：

| 缺陷 | 后果 | 换成 HTML 后 |
|---|---|---|
| 字重饥饿 | 只有微软雅黑 3 档，层级只能靠字号拉 | 思源宋体/黑体可变字体，100–900 全档 |
| 零材质 | 纯色块、直角、发丝线，像 PPT | 渐变、阴影、模糊、混合模式、纸纹噪点 |
| 过度规整 | 处处等距，机器的整齐就是 AI 味 | 旋转、错位、出血、手绘 SVG |

**结论：卡片一律走 HTML 引擎。pptx 只作历史归档，不再用于新成稿。**

## 二、硬性规格

- **尺寸**：`1242 × 1656`（3:4），渲染 `deviceScaleFactor=2` → 2484×3312
- **页边距**：左右各 `96px`，内容宽 `1050px`
- **安全区**：距底 ≥ `40px` 不放内容（防贴边）；正文最后一块离底 ≥ `78px`
- **字体**：`file:///C:/Windows/Fonts/` 绝对路径加载（本机已验证存在）
  - 思源宋体 `NotoSerifSC-VF` / 思源黑体 `NotoSansSC-VF` / 楷体 `simkai` / 等线 Light `Dengl`
- **图片**：先用 `scripts/fetch_shots.js` 抓真实截图，落成稿目录 `shots/`，HTML 里用 `file:///` 绝对路径引用

## 三、四个主题

| 主题 | key | 气质 | 用在哪 |
|---|---|---|---|
| **杂志编辑** | `editorial` | 米白纸底 + 宋体 900 巨标 + 砖红点睛 + 纸纹 | 周日周刊、论文深读、收藏向 |
| **深色舞台** | `stage` | 近黑底 + 金色渐变 + 发光截图托起 | 每日热点**封面**（缩略图最抓眼） |
| **手绘批注** | `notebook` | 楷体 + 荧光笔 + 红圈箭头 + 纸胶带 | 每日热点**内页**（社会/争议话题） |
| **实验室仪器** | `instrument` | 近黑 + 荧光青 + 等宽 + 网格取景框 | 技术硬题材（模型/benchmark/开源） |

**默认组合（2026-10-21 定）**

- **周日周刊**：全套 `editorial`，封面到底卡一个主题走完
- **每日热点**：封面 `stage`（保点击率）+ 内页 `editorial`（保阅读）
- **社会/争议话题**：内页换 `notebook`，靠红圈箭头指出「就这一个点」
- **技术硬题材**：整篇换 `instrument`

每张卡自带主题作用域（背景、文字色、字体、噪点都内联），所以同一份 HTML 里可以混主题。

## 四、组件 API

```js
const C = require("E:/自媒体运营/ai-paper-to-xhs/skill/assets/卡片-HTML/cards.js");
const d = C.makeTheme("editorial");   // 或 stage / notebook / instrument
const cards = [];
cards.push(d.cover({...}), d.toc({...}), d.paper({...}), d.tail({...}));
fs.writeFileSync("卡片.html", C.build({ theme: "editorial", cards }));
```

| 组件 | 用途 | 关键参数 |
|---|---|---|
| `cover` | 封面 | `title[]`、`accentWord`（末行变红斜体）、`lead`、`shot{x,y,w,h,rotate}`、`shotNote`、`stats`(HTML串)、`source` |
| `toc` | 目录卡 | `rows[{n,en,cn,likes}]`、`punch`（金句填空）、`note` |
| `paper` | 论文精华卡 | `no`、`tag`、`title`、`shot{y,h}`、`caption`、`num`、`numLabel`、`bandTop`、`why` |
| `content` | 通用内容卡 | `eyebrow`、`title/titleLines`、`sub`、`shot`、`items[{n,lead,desc}]`；notebook 另有 `annotation{circle,arrow,text}` |
| `compare` | 双图对比 | `shots[2]`、`items`、`quote` |
| `tail` | 尾卡 | `lines[]`、`sub`、`index[]`（编号索引条）、`source` |

`title` / `lead` / `sub` / `punch` 支持内联 HTML（`<br>`、`<span style>`）；`esc()` 只作用于纯文本字段。

## 五、排版铁律

### 5.1 层级只靠字重和字号，不靠装饰
- 标题 `900`，正文 `300–400`，**中间档（500–600）不要用**——两档对比才有杂志感
- 一个强调色，全卡出现不超过 **3 处**（一个标题词 + 一个数字 + 一条短线）

### 5.2 留白断层必须填补
底部或中段空白 **> 300px** 时，三选一：
1. **金句压舱**：左竖线 + 一句判断（`toc` 的 `punch`）
2. **索引条**：一排编号小字（`tail` 的 `index`）
3. **视觉放大**：正文字号上调一档、`line-height` 拉大

**绝对禁止**用 `margin-top:auto` 把最后一块硬推到页面底部，制造断层。

### 5.3 单卡容量
一张卡最多 **1 个大标题区 + 3 个内容模块**。超过就拆卡，不要压字号。

### 5.4 真实素材的环境
截图不能裸贴。至少给一样：
- 轻微旋转（`-1.6° ~ 1.4°`）+ 投影
- 右/下出血（图超出画布边缘）
- 边框 + 地址栏外壳
- 白卡承载（像拍在桌上）

### 5.5 中英混排
- **不要在中文里用空格分隔英文**——楷体/宋体的半角空格是全角宽度，124px 标题会裂开 120px
- 用 `<span style="margin:0 .16em">` 控距
- 数字用衬线或等宽，中文用宋体或黑体，一卡内不混第三种

### 5.6 配色禁区
- `editorial` 主题**禁用蓝色系**（会立刻变成「AI 生成的 PPT」）
- 深色主题的荧光色只做主色，不做面积色
- 背景不用纯黑纯白（`#08090C` / `#F5F2EA` 这类才不刺眼）

## 六、数据一致性铁律（2026-10-21 加的教训）

W42 改版时踩了两个真实的坑，都写进流程：

1. **换版式时不许顺手改文案**
   改标题时把「电脑 Agent 全开源栈」错配到了 VideoJev 的截图上，标题和图对不上。
   → **截图、标题、数字三者在数据数组里必须写在同一行，改一个必须看另外两个。**

2. **赞数必须有出处**
   之前从聚合站抄的「Waypoint 664 赞」在官方周榜上站不住（它排第 14，榜首才是 555）。
   → 卡片上的每个数字，要么能在当次截图里直接读到，要么注明来源和快照时间。
   → 排序口径必须写在卡面上（例：「按我这周的阅读顺序排，不是按赞数」）。

## 七、渲染与自检

```bash
# 1. 生成 HTML
NODE_PATH=C:/Users/Lenovo/.workbuddy/binaries/node/workspace/node_modules \
  "C:/Users/Lenovo/.workbuddy/binaries/node/versions/22.22.2-6/node.exe" 卡片.js

# 2. 渲染 + 自检
NODE_PATH=C:/Users/Lenovo/.workbuddy/binaries/node/workspace/node_modules \
  "C:/Users/Lenovo/.workbuddy/binaries/node/versions/22.22.2-6/node.exe" \
  "E:/自媒体运营/ai-paper-to-xhs/skill/assets/卡片-HTML/render.js" \
  --html 卡片.html --out ./cards
```

`render.js` 自动检查：缺图、文字越界、文字被容器裁切、资源加载失败。
`文字被裁 Npx` 多是中文字体行高溢出的**误报**（10–40px 属正常），超过 40px 再当真。

**渲染完必须逐张 Read 看一遍**——自检只能查几何越界，查不了「标题和图配错了」。

## 八、常见坑

- `-webkit-box-reflect` 的 mask 渐变方向容易反，倒影会越往下越亮并压住底部元素。深色卡慎用倒影
- `object-fit:cover` + 容器比例和原图差太多时，会把截图关键信息（赞数、标题）裁掉。先算比例再定容器
- 混主题时，全局 `.card` 样式只认 `build()` 传入的那个主题；每张卡已内联背景/字体，但 `.kicker`/`.stats` 这类公共类仍是全局的
- Playwright 截图偶发 `waiting for element to be stable`，重跑一次即可
